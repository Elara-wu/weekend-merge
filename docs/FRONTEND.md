# 前端体验与接入说明

## 入口与视觉

正式开发目录为 `D:/workspace/weekend-merge`。此前 `D:/workspace/WeekendMerge` 是独立设计原型，不作为正式代码入口。

前端采用奶油白、森林绿、鼠尾草绿与中文衬线标题；首屏直接创建计划，右侧使用城市周末手账式配图。

| 模块 | 入口 |
| --- | --- |
| 应用壳、步骤导航、演示事件播放 | `src/app/App.tsx` |
| 创建、独立偏好、共识 | `src/features/wizard/` |
| 三栏工作台、事件投影、局部替换入口 | `src/features/workbench/` |
| 最终行程、PNG 与只读分享 | `src/features/final/` |
| 路线示意与可访问对话框 | `src/components/` |
| 持久化会话与协商动作 | `src/state/usePlanningStore.ts` |
| 视觉 token、主样式与适配 | `src/styles/` |

## 数据与状态边界

- 复用 `src/contracts/agent.ts` 中的 `PlanSetup`、`PersonPreferences`、`Itinerary` 和 `AgentEvent`，未新增并行共享协议。
- `PlanningWorkbench` 继续接收 `events: AgentEvent[]`。候选按 ID 去重，展示等待、运行、部分完成、完成、降级与失败状态。
- UI 从工具事件读取天气、耗时、来源和摘要，不展示模型隐藏思维链。
- 使用已有 Zustand store 和 `weekend-merge-session` 存储键，新增选中方案/站点、点赞、锁定、替换记录及最终方案持久化；旧会话缺少字段时使用默认值。
- 费用展示直接读取 `Itinerary.totalCost` 与站点费用；当前契约未提供缓冲拆分，因此前端不声称已包含 10% 缓冲。
- 共享 Schema、演示 fixture、Netlify 函数与项目依赖保持原样，后续后端可沿用既有事件接入。

## 关键交互

- 创建页校验未来 14 天内的周末、3–12 小时时段和 ¥100–2,000 双人预算；起点限定预设商圈。
- A 提交后卸载表单，交接页不显示答案；B 返回 A 前需确认设备交接。兴趣最多五项，支持顺序调整。
- 共识依据实际双方输入计算，展示共同兴趣、各自兴趣、步行/时间/预算与雷区。
- 地图序号与站点详情联动；手机候选在地图上方，行程和轨迹互斥，站点操作固定底部。
- 喜欢与锁定分别保存；锁定站点不可否决，后端已锁定站点不可由 UI 解锁。
- 否决必须选理由，补充文本最多 60 字。最多两轮，已替换站点不可重复替换。
- 最终 PNG 导出不依赖远程图片；只读分享只保存方案和公共条件，不保存双方偏好。URL fragment 中的 JSON 通过现有 Zod Schema 验证，并限制小于 6 KB。

## 当前演示边界

- Agent 仍使用仓库 `createDemoRun()`；页面定时播放这些事件，未新增真实 DeepSeek 或 HTTP 流请求。
- 方案仍是固定 fixtures；创建条件不满足演示方案时禁止确认，不暗中放宽条件。完整营业时间、饮食、起点与路线验证由后端负责。
- 地图为原创 SVG 示意，按地点坐标投影展示；并非 Leaflet 或实时导航。
- 局部替换是明确标识的同区域、同坐标、等费用演示；保护原时段与其他站点。真实替代检索、邻接交通重算仍待 `replan` 接口。
- 分享使用 Base64 编码，尚未做压缩。个人偏好存在 localStorage，私密交接不是加密存储。
- 配图来源：[上海街区参考图片](https://www.sohu.com/a/435877770_260616)。设计预览使用，公开商业发布前替换为确认授权的素材。

## 验证

运行 `npm test -- --run` 和 `npm run build`。

自动化测试覆盖原有组件/Schema/函数，以及锁定保护、两轮上限、事件重放去重、分享 Schema 和体积限制。浏览器演示路径：创建 → A/B 独立输入 → 共识 → 规划 → 锁定晚餐 → 替换展览 → 刷新恢复 → 最终行程 → 导出。
